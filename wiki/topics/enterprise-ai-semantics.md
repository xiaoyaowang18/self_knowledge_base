# 企业 AI 的语义基础与安全执行

## 当前结论

可靠的企业 AI 应沿着“产品目标 → 数据架构 → 业务语义与约束 → 受控执行”的顺序建设：先明确要解决的业务问题和数据流，再把关键对象、关系、阈值、权限和动作写成可审查规则，最后让 Agent 在真实业务对象上检索、推理和执行。Ontology 能承载这层语义，但不能替代数据治理、组织裁决和持续维护。

## 支持证据

- `note-20260827-0e421aa2`：本体的核心是对象、属性、关系、约束和动作；跨系统语义统一、结构化检索、权限和审计共同构成 Agent 安全执行的基础。
- `note-20260822-499f8a7e`：产品和架构应先用“进、存、取”理清数据旅程，保护原始事实，再决定实现方式和扩展边界。
- `note-20260822-2d9fb61e`：AI 编程应以产品、架构和选型为上下文，分步施工、逐步验证，并把语义判断与机械任务分开。

## 反例或矛盾

- 复杂语义层并非所有 AI 应用的起点；简单 FAQ 或资料搜索可能只需要高质量内容、检索和引用。
- “本体 + 动作 + 权限”可以提高 Agent 的可控性，但如果组织没有统一概念和数据质量，建模只会把分歧显性化，不能自动解决分歧。
- AI 可以生成架构、代码和规则草稿，但需求取舍、概念裁决、权限边界和验收责任仍属于人。

## 仍待确认的问题

- 当前个人知识库中，哪些概念已经复杂到需要显式约束，而标签和关联仍不足以表达？
- 如果未来加入 Agent 执行，最小可接受的审批、权限和审计边界是什么？
- 何时应从可解释的 Markdown／关键词方案升级到更正式的语义模型或图检索？

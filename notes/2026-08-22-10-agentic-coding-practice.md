# Vibe Coding 实战：从架构到第一个能跑的产品

## 一句话结论

可靠的 AI 编程不是一句话生成完整产品，而是先提供产品、架构和选型上下文，再分步派活、逐步验证、根据真实错误返工，并让 AI 与脚本各自承担合适任务。

## 核心信息

- 文章用“包工头与施工队”类比 Agentic Coding：人负责讲清需求、分阶段验收和判断返工，AI 负责具体实现。
- 开工前应把一页纸 MVP、架构文档和技术选型交给 AI，并让它复述确认理解。
- fuxi 的第一个功能从入口开始：按规则抓取链接、提炼内容、打标签并生成笔记。
- 语义判断交给 AI 当场处理；规则明确、重复执行的搜索等机械任务由 AI 写成脚本。
- 实施方法是拆小步、每步运行、用真实输入验证；报错时保留原始信息交给 AI，持续卡住时应换策略而不是盲目试错。

## 我的判断

这篇资料把前面的产品、架构和技术思维合并成可执行方法。核心不是“不会代码也能做产品”的口号，而是用上下文、任务拆分和验证机制承担原本由工程经验完成的管理工作。AI 降低实现门槛，但没有取消需求和质量责任。

## 可用场景

- 用 Claude Code 或 Codex 启动个人 MVP。
- 决定某个能力应写成脚本还是交给 AI 实时判断。
- 设计 AI 编程任务的分步验收过程。
- 解释 Vibe Coding 与可控 Agentic Coding 的区别。

## 证据与限制

- “Vibe Coding 已过时”等表述是作者判断，不是统一行业定义。
- 直接把错误信息交给 AI 适用于普通开发问题；涉及密钥、隐私数据或外部协议时仍需脱敏并核对官方资料。
- 文中案例是个人本地知识库，不能直接代表高风险或生产系统的工程要求。

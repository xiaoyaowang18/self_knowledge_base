# Skill：把好用的 Prompt 变成一键技能

## 一句话结论

当同一类 Prompt 被反复使用时，应把角色、任务、输出格式和约束固化成可复用 Skill，并通过真实案例测试迭代，而不是每次从零描述。

## 核心信息

- Skill 被定义为面向具体重复场景的 Prompt 说明书；一次性任务不必固化，重复任务才值得建立技能。
- 最小结构包括角色、任务、输出格式和约束，创建过程是锁定场景、写初版、用真实素材测试、保存复用。
- 示例、自检清单、动态变量和 Skill 组合链可以提高输出稳定性并覆盖相近变体。
- 不会从零编写时，可让 AI 先生成 Skill 初版，再由使用者删减、补边界并测试。
- 文章建议不要全局安装大量 Skill，应优先保留高频通用技能，项目专用技能只放在对应项目中。

## 我的判断

Skill 的核心价值是把偶然有效的提示词升级为可审计、可测试、可迭代的工作标准。判断是否值得固化，应该同时看重复频率和输出稳定性；只有真实运行过的规则才是技能，未经验证的长 Prompt 仍只是草稿。

## 可用场景

- 把会议纪要、周报、写作风格等重复任务固化。
- 设计 Claude Code 或 Codex 的项目级技能。
- 为 Skill 增加样例、自检和可变参数。
- 评估是否应安装或创建某个新技能。

## 证据与限制

- 文章关于 Claude Code、Codex 的目录和调用方式具有版本时效性，实际使用前应查看对应产品官方说明。
- “同一个 Prompt 写三遍就固化”是经验阈值，不是强制标准；低频但高风险的任务也可能值得标准化。
- Skill 能稳定流程，但不能自动保证输入事实、判断质量和最终结果正确。
